# Как предложить правку

## Страница документации

Нажмите «Редактировать страницу» внизу страницы или измените файл в `src/content/docs/` и откройте pull request.

## Нормативный документ (устав, регламент, whitepaper)

1. Измените исходник `documents/<id>/v<версия>.typ`.
   Существенное изменение — новая версия: скопируйте файл в `v<новая>.typ` и добавьте её **первой** в `versions` в `meta.yaml`.
   Если правку готовили с ИИ, добавьте в документ раздел «Использование ИИ»: что подготовлено с ИИ и что проверено человеком. Если ИИ не применялся — так и напишите (Регламент использования ИИ, разд. 3).
2. Обновите пересказ документа в `src/content/docs/` — ссылка на него указана в поле `related` в `meta.yaml`.
3. Откройте pull request. Его одобряют ответственные из `.github/CODEOWNERS`.
4. После утверждения заполните в `meta.yaml` поля `date` и `approved`.

Старые версии не удаляются и не меняются: их хеши уже могли сохранить участники.

## Приложения к документу

К версии документа можно приложить обоснование, финансовые расчёты, исходные данные и другие файлы. Они показываются на странице документа в блоке «Приложения» с размером и SHA-256. Загрузить или изменить приложение можно только через репозиторий — на сайте их нельзя редактировать.

1. Положите файл в `documents/<id>/attachments/`. Имя — латиницей, цифрами, `-`, `_` и `.`, лучше с номером версии: `v0.2-runway.xlsx`.
   - Текстовое приложение (обоснование, пояснительная записка) пишите на Typst — оно соберётся в PDF в общем оформлении: `#show: doc.with(title: "…", kind: "Приложение", version: "0.2", status: "draft")`.
   - Расчёты и данные кладите как есть: XLSX, ODS, CSV, PDF и т. п. Держите файлы небольшими — до нескольких мегабайт.
2. Перечислите приложения в `meta.yaml` у нужной версии:

   ```yaml
   versions:
     - version: "0.2"
       source: v0.2.typ
       attachments:
         - title: Обоснование изменений
           description: Почему меняется распределение казны.
           source: attachments/v0.2-rationale.typ   # Typst → PDF
         - title: Финансовая модель
           description: Расчёт запаса казны на 24 месяца.
           file: attachments/v0.2-runway.xlsx       # готовый файл
   ```

   У каждого приложения ровно одно из полей: `source` (Typst) или `file` (готовый файл). `description` — необязательно.
3. Откройте pull request, как для правки документа.

Приложения относятся к конкретной версии и, как и сама версия, после утверждения не меняются. Исправленный расчёт — новый файл в новой версии документа. Если приложение не изменилось, новая версия может ссылаться на тот же файл.

## Новый документ

Создайте папку `documents/<id>/` с `meta.yaml` (образец — `documents/charter/meta.yaml`) и исходником. Если исходника нет, положите готовый PDF и укажите его в поле `file` вместо `source`.
